# 0001. 전처리 계층별 품질 가드 도입

## Status

Accepted

## Context

`ImagePreprocessor`는 5계층(기울기 정렬 → 원근 복원 → TPS 곡면 복원 → DocTr 주름
보정 → 조도 개선) 파이프라인으로, 각 계층은 예외 발생 시에만 건너뛰는 구조였다.
그러나 [failures/0001](../failures/0001-tps-dewarp-destroys-image-ocr-no-text.md)에서
드러났듯, 계층이 **예외 없이 성공적으로 실행되면서 이미지를 파괴**하는 경우가 있다
(TPS 변환 발산 → 출력 전체 단색 → CLOVA OCR NO_TEXT). 기하 보정 계층은 입력 사진의
형태에 따라 추정이 퇴화할 수 있어, 개별 버그를 고치더라도 같은 부류의 사고가
재발할 수 있는 구조적 위험이 있다.

## Decision

`_safe_apply`(모든 계층의 공통 실행 래퍼)에 품질 가드를 추가한다:

- 계층 실행 후 텍스트 가독성 지표 2종을 입력과 비교한다 —
  **Canny 에지 밀도**(텍스트 획 존재량), **명암 표준편차**(대비).
- 둘 중 하나라도 입력의 **절반 미만**으로 떨어지면(`_GUARD_EDGE_RATIO = 0.5`,
  `_GUARD_CONTRAST_RATIO = 0.5`) 보정이 텍스트를 파괴한 것으로 판단,
  해당 계층 결과를 버리고 이전 단계 이미지를 유지한다. 폐기 시 전후 지표를
  warning 로그로 남긴다.
- 결과 객체가 입력과 동일(`result is img`)하면 지표 계산을 생략한다.

## Rationale

- OCR 전처리의 제1원칙은 "원본보다 나빠지지 않는다"이다. 보정은 가산점이고,
  파괴는 분석 결과(UNKNOWN)로 직결되는 치명상이다.
- 특정 계층(TPS)만 고치는 것이 아니라 래퍼에 두어, 미래의 계층 추가·수정에도
  동일한 방어가 자동 적용된다.
- 지표 계산(Canny + std)은 이미지당 수 ms 수준으로 OCR 왕복(수백 ms~초) 대비
  무시 가능한 비용이다.
- 임계 0.5는 보수적으로 잡았다: 정상 보정(회전, 원근, CLAHE)은 에지·대비를
  유지하거나 늘리는 반면, 파괴 사례는 0 근처로 추락해 두 분포가 멀리 떨어져
  있다. test1~3 회귀에서 오탐(정상 보정 폐기) 없음을 확인했다.

수용한 트레이드오프: 가독성 지표를 통과하는 수준의 "미세한" 기하 왜곡은 가드가
잡지 못한다. 이는 가드의 목적이 아니며, 개별 계층의 정확성 문제로 다룬다
(예: TPS 방향 버그는 별도 수정).

## Alternatives Considered

- **TPS 버그만 수정하고 가드 생략**: 같은 부류(추정 퇴화 → 출력 파괴)의 사고가
  다른 계층·다른 입력에서 재발할 때 다시 OCR 전면 실패로 이어진다. 구조적 방어가
  아니므로 기각.
- **OCR 결과 기반 재시도 (NO_TEXT면 원본으로 재호출)**: 확실하지만 실패 케이스마다
  CLOVA 호출이 2배(비용·지연). 런타임 사전 차단이 더 저렴해 기각. 단, 추후
  방어선이 더 필요하면 보완책으로 고려 가능.
- **전처리 전체 폐기 후 원본 사용**: 정상 동작하는 계층(조도 개선 등)의 이득까지
  버리게 되어 기각. 가드는 문제 계층만 선별적으로 무효화한다.

## Agent Guidance

- 전처리 계층을 추가하거나 수정할 때 `_safe_apply`를 우회하지 말 것 — 예외 안전과
  품질 가드가 모두 이 래퍼에 있다.
- 새 계층이 의도적으로 에지·대비를 크게 줄이는 경우(예: 강한 블러)는 이 파이프라인의
  목적(OCR 가독성)과 충돌하므로 설계를 재고할 것.
- 전처리 관련 OCR 실패가 의심되면 `scripts/debug_preprocess_steps.py`로 계층별
  중간 이미지·지표를 먼저 확인할 것.
- 가드 임계(0.5)를 조정할 때는 test1~3 회귀(`scripts/clova_ocr_live_test.py`)로
  오탐·미탐을 함께 확인할 것.
